Training route

→ engine/trainer.py → model(images, targets)
→ backbone → FCOS → ParsingHead → loss dictionary

Evaluation route

test_CIHP_R50_75epoch.sh → tools/test_net_parsing.py
→ engine/parsing_inference.py → engine/test.py
→ model.box_net → model.parsing_net
→ post_processing → evaluation

Evaluation uses saved weights and does not update parameters. eval() changes module behavior; no_grad() disables gradient tracking. These have separate purposes. See PyTorch Quickstart.

Glossary

Tensor: numeric array. Parameter: learnable tensor. Backbone: image feature extractor. FPN: feature pyramid supplying multiple spatial scales. Proposal / region: candidate person box. RoI: region of interest. Logit: raw class score. Target: known training answer. Loss: scalar training objective. Gradient: sensitivity of loss to a parameter. Optimizer: applies parameter updates. Checkpoint: saved model state, potentially with optimizer and scheduler state.

Details that can mislead a new contributor

  • models/ and utils/ contain imported supporting code; the active top-level model lives under maskrcnn_benchmark/. Follow imports rather than similarly named files.
  • RPN_ONLY: True does not mean parsing is absent here: GeneralizedRCNN explicitly constructs ParsingHead.
  • The training script's automatic final test call is commented out. The shell evaluation script is a separate route.
  • Direct evaluation through GeneralizedRCNN.forward has a visible return-count mismatch: it unpacks three values from ParsingHead, whose test branch returns four. The supplied parsing evaluation route calls box_net/parsing_net instead. This is a static finding, not a tested bug fix.
  • The README specifies Python 3.7, PyTorch 1.7.1, CUDA 10.1 and compiled extensions. Modern tutorial installation instructions are not a verified environment recipe for this checkout.
