01 · Where learning happens

Your win: distinguish building a model, running it, and changing its learned numbers. Allow about six minutes.

This project performs instance-level human parsing: find individual people and assign part labels within each person's region. We follow the CIHP ResNet-50 configuration.

1. A model is a Python object holding learned numbers

A tensor is an array of numbers. A parameter is a tensor the model can learn. A PyTorch nn.Module groups parameters and computations. Its __init__ builds layers; forward describes computation. Calling model(...) invokes that computation through PyTorch's module machinery. See the official Quickstart.

Open maskrcnn_benchmark/modeling/detector/generalized_rcnn.py. In __init__, find self.backbone, self.rpn, and self.ParsingHead. These are the three major pieces.

image → backbone features → FCOS person boxes → parsing head → part predictions

The YAML sets FCOS_ON: True. The builder in modeling/rpn/rpn.py therefore selects FCOS despite the attribute name rpn. Follow the selected branch, not the old name.

2. Training asks how wrong the predictions were

In forward, the backbone processes images.tensors. FCOS returns proposals and detection losses; the parsing head returns parsing-related losses. During training the top-level model combines these into a dictionary. The labels supplied in targets are the known answers.

Open maskrcnn_benchmark/engine/trainer.py and find this sequence:

loss_dict = model(images, targets)
losses = sum(loss for loss in loss_dict.values())
optimizer.zero_grad()
losses.backward()
optimizer.step()

zero_grad clears accumulated gradients. backward computes gradients: how the loss changes with parameters. step uses those gradients to update parameters. A lower loss is the training objective, not a guarantee of better unseen-image performance. Primary reading: PyTorch optimization.
